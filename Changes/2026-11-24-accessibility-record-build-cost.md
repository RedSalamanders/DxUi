- A UI Automation snapshot build reads each control once and only what it has (performance plan `W8.3`): the walk that counts the records also indexes every mnemonic `Label` by target, so naming an unlabelled field, check box, toggle or slider no longer walks the tree; each library control class records its kind when it is constructed and the accessibility code tests that kind instead of chains of `dynamic_cast`; a `TextField`'s and an editable `ComboBox`'s value and TextPattern text, and the focused control's native text-input cache, are borrowed as the control's shared immutable text instead of copied; and a record is a hot core with separate text, range, grid, tree and tab parts (376 B per record without a part on x64 Release, was 936 B). Rectangles are kept relative to their scroll scope (the content of the nearest `ScrollPanel`) and resolved when read, so a `ScrollPanel` scroll publishes by moving its scope, re-reading no record and sharing every rectangle; a `Grid`'s or `Tree`'s wheel scroll is a declared scroll of that control and no longer builds the whole window. A scroll is published at once, never held by the coalescing of geometry-only publications. On `FX12`'s 10,000-control form with one client a build makes 0 label walks, 0 `dynamic_cast` and 0 text copies (the reads before `W8.3`, kept as a test seam, make 6,000 walks, about 6 x 10^7 casts and 4,000 copies), and `FX3`'s 100 wheel notches publish with no whole build, each re-reading at most the grid's record. A successor finds each control it re-reads down its record's path instead of searching each parent's children, so a layout moving every control of a 10,000-control form publishes incrementally in about half a whole build's time (it took three times as long) and never reads more of the tree than a whole build. Every incremental publication is still compared field by field with a whole build, rectangles both stored and resolved. A window host still builds the whole window after a handled wheel message. Validated by the Accessibility, Embedded, WindowHost, Control, Rendering, Grid, Tree, ComboBox and TextField suites; receipt in `Measurements/PerformanceAndMotion_2026-11-13/W8.3`.
