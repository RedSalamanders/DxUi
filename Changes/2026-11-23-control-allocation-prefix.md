- Control object allocation (`src/Foundation/ControlAllocation.cpp`) now costs 16 bytes per control instead of 39 plus the heap's rounding: the default-alignment path of `Control::operator new` keeps a 16-byte `{requested, accounted}` prefix and drops the back-pointer and the 15 bytes of alignment slack, because `HeapAlloc` already returns `MEMORY_ALLOCATION_ALIGNMENT` (16-byte) blocks on x64 and ARM64 (checked at compile time, and a Debug build stops on a misaligned block). `HeapSize` is read only for a block allocated while `Diagnostics::nativeAllocationSink` is set, counted by the new work counter `memory.controlHeapSizeReads`; a block allocated with no sink records `accounted` as 0 and its free is never reported, so a sink installed or removed between a block's allocation and free keeps its live bytes and counts exact. An over-aligned control keeps its 24-byte header and is freed through the aligned `operator delete`. No public type or signature changes. Validated by the new `Foundation.Tests.ControlAllocation.cpp` (exact 16-byte overhead through the accounting, alignment of every kind, a round trip of every overload pair, sink set before, after and toggled, no `HeapSize` without a sink; the overhead check was observed failing on the base first); the `FX12` 10,000-control form measures live tracked bytes per simple control before and after under `Measurements/PerformanceAndMotion_2026-11-13/W9.6`. The `G13` per-control line is still over 256 bytes: moving cold `Control` fields into an optional block (the second half of `W9.6`) stays open.
