- Tests that asserted the desktop foreground was unchanged now assert the claim about their own window: the host under test never takes the foreground (`GetForegroundWindow() != window`), so another application changing the foreground while a suite runs no longer fails `RichSemanticGeometry`, `WindowHost` (caption hover and logical editor focus), the masked-input IME policy and the fatal-child activation guard; the latest-source, focus and activation-blocker assertions stay as strict as before, and the focus-taking suites are unchanged.
