# Cooperative geometry API sketch - unimplemented

Start after the frozen positioned-line qualification closes. Do not imply that
this sketch is a scheduler, a hard time bound, large-file support or final D2a.

PreparedDocumentLayout can expose BeginPreparation, AdvancePreparation and
CancelPreparation while its existing Prepare drains those same phases. A private
Preparation object owns the complete staged State, source-change interval,
compatibility keys, block cursor, compaction pass and phase. No asynchronous raw
pointer/callback is introduced by the pure core. All calls stay on one owner.

An unchanged request must retain the existing zero-allocation path. A changed
Begin builds new staging fallibly before replacing an older pending request.
Published state/revision/generation remain unchanged until nonthrowing commit.
An owner may explicitly Invalidate published geometry as today before starting
the current revision; pending work never makes that old geometry current.

Advance phases:

1. Prepare immutable projection/indexes (currently indivisible v0 work; later
   borrow a revision-tagged worker result rather than pretend it is resumable).
2. Reuse or prepare bounded chunks, retaining the exact origin condition. Limit
   new SDK layouts per advance; reusable block walking also needs an independent
   finite work budget. One long physical line can exceed the source-unit target;
   expose that limitation honestly and qualify viewport segmentation separately.
3. Compaction resets only staging, counts all abandoned/rebuilt work and advances
   over subsequent calls. Keep 127 chunk slots plus the optional reference slot.
4. Whole compatibility preparation is its own explicit SDK work unit and counts
   full source units; it is not hidden behind a supposedly completed step budget.
5. Commit source/mapping/geometry together and increment generation once.

If a named standard/WIL staging exception occurs in any advance, discard pending
state and rethrow; a partially appended chunk cannot be retried as though its
cursor had advanced. The published graph, revision, generation and statistics
remain intact. Cancel/Clear/Invalidate must retire pending state without creating
Debug STL proxy containers inside noexcept paths. Clear releases both graphs;
Invalidate retains reusable published geometry but cancels obsolete staging.

Status and progress need separate fields from LastPreparation, which describes
the published revision. Explicit pending statistics may expose prepared/reused/
whole/source work and remaining source without misrepresenting current geometry.
No numeric revision alone establishes identity. Requests carry immutable source,
mode, factory identity, options, host binding and device/typography generation.
The control/host must reject stale completion before final composition/text/UIA.

Tests before host integration: exact equivalence for budgets 1/2/unlimited;
unchanged zero allocation; bounded reuse-only walking; every chunk/reference/
compaction boundary; changed-origin suffixes; all failure points in begin and
every advance; cancel before/between/after phases; replacement request, equal
numeric revision/different source, retirement and retry; default/tiny fonts,
hidden suffixes, source/map/geometry/pixels, resource peaks and zero release delta.

Host integration still must audit every EnsureLayout caller. Synchronous TSF/UIA
geometry calls cannot drain the full request while painting happens cooperatively.
Pending geometry returns unavailable and publication waits for one coherent
revision. Native and embedded wakeups borrow existing host services, remain event
driven, coalesce updates and create no per-control worker/timer/device/HWND.
