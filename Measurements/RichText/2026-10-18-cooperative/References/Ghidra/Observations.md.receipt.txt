# Saved Office work/completion evidence

Actual registered Ghidra MCP run_script_inline calls opened the saved Office
program read-only. No import, analysis, transaction, rename, save or active-program
switch occurred. Hash 7f810b35cd2f818b70475d865ef743860b40cefe463e60d2f1c2de5bd2c6aa41
matches the pinned reference; the earlier inventory labels it Office
16.0.20430.20032. This is not a check of today's installed DLL.

The first script enumerates 9,706 functions and 19 bounded display-recalculation
matches. The second verifies eight exact names/addresses before decompiling.
All eight C outputs are nonempty and hashed. MCP's nested success and script
console completion agree with the actual inventory. Both program-list reads keep
one open program, user32.dll; the saved Office program has programChanged=false.
Original script source, MCP framing/schema/results, stderr and outputs remain.

Observed in this build:

- CDisplayEngineML::StartBackgroundRecalc, RVA 0x1a5324, checks state/progress,
  calls CTxtEdit::TxSetTimer with ID 0x1af and interval 300, updates flags after
  success and uses a synchronous dispatched fallback when setup fails. Its name
  does not establish a background thread or a nonblocking failure path.
- CDisplayEngineML::IsBackgroundRecalcDone, RVA 0x203160, compares stored progress
  against a story-associated length. Keep the actual arithmetic; private field
  identities and ownership are not independently established by offsets alone.
- CDisplayEngineML::StepBackgroundRecalc, RVA 0x203220, builds a rich-text pointer
  from stored progress and calls RecalcLines for the remaining extent. This small
  wrapper supplies no hard CPU-time budget; the larger callee decides work.
- CDisplayML::WaitForRecalcIli, RVA 0x14be50, has a pending/step loop and an early
  state/position condition. Indirect calls and some recovered locals remain
  uncertain. It is not evidence that a current-geometry request is always cheap.
- CDisplayML::WaitForRecalcView, RVA 0x14ceb0, dispatches a view extent through a
  virtual target. Its raw pseudocode includes unresolved-jumptable warnings even
  though the decompiler's top-level error string is empty; do not erase them.
- CDisplay::FLayoutRecalcPending, RVA 0x14da00, tests stored pending flags and an
  associated state pointer. Do not copy private flags into the owned control.
- CDisplay::RequestStrongRecalc, RVA 0x544d0, clears contexts/layout caches and
  widens a stored invalidation extent; it differs from a continuation step.
- CDisplayML::RecalcLine, RVA 0x204c80, publishes a post-replacement notification
  through CNotifyMgr when the relevant story/notification manager exists.

Owned design inferences, not recovered original C++: explicitly separate
invalidation, pending work, bounded advances, completion and retirement. Geometry
queries while pending must not silently drain a whole document. Failed scheduling
must preserve source and recover through a documented host path rather than block
input or invent a per-control timer. Use the existing DxUi host/application
services, lifetime/binding/revision keys, stale-result rejection, coalescing and
atomic source/geometry/pixel publication. Add native/embedded cancellation and
failure tests before marking the cooperative component implemented.

These reads do not change the positioned-line qualification or resolve scheduler
latency/frame-performance HOLD, full Markdown, helper deployment or physical AT.
