# Parser boundaries after cooperative geometry

Private design draft, not implemented or qualified. Do not mutate frozen active
source/spec/test inputs to incorporate this draft during qualification. Continue
using the one indexed RichTextEditor WIP plan; this is not another active plan.

The user requests an owned Unicode C++ engine and inspiration from the three
public parsers. Nine exact README/API/license snapshots and their commit-addressed
URLs are in the parser reference receipt. No parser dependency is chosen here.

| Reference | Useful boundary | Limit of the evidence |
| --- | --- | --- |
| MD4C | Block/span/text callbacks, explicit lengths, Windows UTF-16 configuration, typed attributes | Callback abort is not resumable pause. Callback text/attributes alone are not a complete lossless syntax model or a general source-range API. |
| Discount | Distinct input, compile and document-output APIs; explicit dialect/feature flags | Legacy strict Markdown compatibility does not qualify a strict CommonMark/GFM profile. |
| cmark-gfm | AST ownership, source-position queries, feed/finish and extension interfaces | Feed is not incremental edit repair or bounded finish. Do not infer UTF-16 offsets from line/column values without a measured adapter. |

## Keep source authoritative

Retain immutable SourceSnapshot identity, source revision and parser profile in
each request/result. Syntax nodes preserve delimiters, trivia and unknown/error
spans rather than reconstructing source from formatted output. Stable node IDs
belong to one document identity, not to offsets or a hash alone. Incremental
reconciliation must account for container/reference dependencies, not just the
edited physical line. The existing v0 line-local widening remains a preview.

Separate source UTF-16 ACP, display UTF-16, grapheme boundaries, and any UTF-8
reference-parser bytes/columns. Exercise supplementary scalars, combining/ZWJ,
tabs, CRLF, entities, generated markers, repeated/reordered footnotes and empty
anchors. Measure a reference API's position convention rather than guessing it.
Original source and primary editing affinity remain recoverable when one source
span produces several display spans or an object has generated display content.

Resolve NUL admission deliberately: the current Document rejects it, while full
CommonMark projects replacement. Preserve the original source/encoding decision
and reconcile codecs, clipboard, TSF/UIA and persistence; do not relax unrelated
font/resource name validation or silently delete source units.

## Make pure parsing resumable before calling it bounded

Use a parser-owned cursor for input scanning, block/container state, reference
dependencies, inline delimiters and semantic/projection construction. Bound and
report actual input/node/dependency work at each phase. A monolithic foreign
parser that aborts after a callback cannot resume merely because geometry has
an Advance API. Joining/building large vectors and pathological delimiter or
container sequences need their own cancellation and storage evidence.

Do not transfer DirectWrite/D2D objects to arbitrary execution threads. Pure
source/parser results can use caller-supplied shared execution later; final
geometry and publication remain on the host owner. No control/view-owned
worker/timer is introduced. Keep one current pending request, cancel superseded
work and validate source identity/revision/profile plus binding/style/width/
resource keys before publication. Out-of-order worker tests become mandatory
when an actual shared execution adapter exists.

## Separate strict profiles and accepted extensions

The pinned CommonMark 0.31.2 and strict GFM 0.29-gfm corpora are separate profiles.
Do not treat a current-head README, parser release or renderer output as proof
of both. Run every pinned example against the owned engine with deterministic
HTML/semantic expectations and retain original source independently. Define
front matter, math, Mermaid and footnotes through explicit extension profiles;
strict CommonMark interpretations must remain available.

Math and diagram render results also carry node/source/profile/resource keys.
Source, accessible alternatives, unknown extensions and failed/pending rendering
must remain editable and preservable. Helper deployment/isolation/offline assets
and source-visible pending/error presentation remain explicit implementation
decisions. HTML output is neither the native control nor an implicit permission
to execute document content.

Required closeout remains code plus independent native/embedded editing,
selection/history, geometry, TSF/UIA and hostile-input/resource tests. The 65,536
UTF-16 source-unit preview limit remains until capacity/latency evidence justifies change;
1-MiB, 10-MiB and 100-MiB targets are not qualified by this scheduling component.
