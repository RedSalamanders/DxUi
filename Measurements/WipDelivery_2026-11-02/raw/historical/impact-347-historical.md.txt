## Impact

The candidate repairs control lifetime/reentry and capture behavior, Grid/Tree and native menu input/UIA, text-store and embedded host lifecycle, build/test evidence, and extends bounded RichMarkdown, math, diagrams, images, file-drop and export. Published behavior and limits belong to `Specs/UI/UI_ControlsAndLayout.md`, `Specs/UI/UI_InputAndAccessibility.md`, `Specs/Rendering/Rendering_EmbeddedD3D11.md`, `Specs/Rendering/Rendering_Win32Host.md`, `docs/rich-text.md` and `docs/hosting.md`. Unsupported content retains source and the documented local fallback; this is not unlimited TeX, Mermaid, SVG or browser compatibility.

API revision remains 4, but C++ object layout has changed: `include/DxUi/RichDocument.h` Document and `include/DxUi/DxUi.h` RichTextEditorDebugState gained data. Consumers must rebuild the full dependent binary closure with the exact matching headers, archive, compiler, runtime and configuration. Equal API numbers or a successful isolated layout probe do not establish binary interoperability (`Specs/Build/Build_ToolchainAndConsumption.md`). Compatibility branch builds and product pin/adoption remain separate from the main candidate.

The accessibility tree now exposes a RadioButtons group with Selection and makes its grouped radio choices children with a real SelectionContainer. Prepared Tree expansion/collapse actions can report a known unfocused item without scanning the full prepared model. Embedded action hints are bounded to 128; a full buffer or conflicting outstanding action returns `ERROR_BUSY` before model mutation. Application-driven replacements that provide no changed IDs still raise structure invalidation rather than claiming an arbitrary item event (`Specs/UI/UI_InputAndAccessibility.md`). These are observable provider and failure-contract changes for UIA clients.

Native visibility and occlusion are supplied by the application through `SetNativePresentationVisible`; the host does not infer arbitrary flip-model occlusion by polling. Embedded visibility remains application-owned (`Specs/Core/Core_PerformanceAndResources.md`). Surface loss suspends composition and input sessions while retaining an owned logical focus; explicit `CancelTextInput` retains its focus-clearing contract. Uncached embedded Grid accessibility materialization uses the current coherent interaction geometry; paint-dirty snapshots can remain valid where the current contract permits them (`Specs/Rendering/Rendering_EmbeddedD3D11.md`, `Specs/UI/UI_InputAndAccessibility.md`).

Image decoding now writes identity-orientation pixels directly into an unpublished owned image buffer; cancellation and failures preserve the caller's previous result. Width-only reflow can reuse a complete bitmap for the same immutable resource, target and epoch; target or epoch changes rebuild it. A focused matched-9c/R23 diagnostic with only the changed image TU measured **2,099,637 → 1,050,998 requested C++ allocation bytes** for a warmed opaque 512×512 PNG; both results matched all 1,048,576 source pixel bytes. The counter excludes SDK/private heap and this is neither a paired performance verdict nor final-candidate qualification. Exact source archives, build commands, EXE/PDB hashes, process identities and outputs are retained in the focused evidence packet.

## Review decisions and boundaries

- The current non-Rich crosswalk covers R28-01–53, CR1–37, DX1–11, CB1–10 and Production Q1–31. Source fixes, bounded contracts and explicit historical exceptions must be reflected individually in the final plan records; a passing suite does not prove every original subclaim. `CodeReview_2026-10-28.md`, `CodeReview_2026-10-10.md`, `DeliveryReview_2026-10-31.md`, `CodexBranchReview_2026-10-02.md` and `ProductionReview_2026-10-05.md` retain their findings and applicable owner contracts.
- Rich audit coverage is indexed by original categories: commands, blocks/inlines, document/geometry/accessibility, editor/critic, semantic, math parser/layout, Mermaid, images/clipboard, host/status and test-engine/test-host. The final source register and C1–C8 target/corpus must be reconciled by ID, including explicit unsupported fallback; code presence alone is not a test result (`Specs/Plans/WIP/RichTextAudit_2026-10-21.md`, `ThirdParty/Markdown/profiles/`).
- W2.8 reduced or bounded specific pending-edit operations, but some prepared v0/Source movement and deletion paths still materialize whole text. A blanket bounded-window rewrite is an unmeasured proposal, not an implemented optimization: a fixed window can cut a grapheme, CRLF, source ownership or selection/history context. Keep exact semantics and investigate a separately measured, correctly bounded design if justified.
- W2.9's early release conflicts with preserving the last good parser publication across pending/canceled work. W2.10's single EOL choice conflicts with distinct documented raw typing/paste and local structural-edit policies; factoring a scanner without changing those policies remains optional. No unmeasured sorted-vector or helper rewrite is claimed complete.
- W4/W5 mandatory generic lifecycle/public-field rewrites are rejected as blanket requirements: parser, semantic builder, geometry and image requests have different publication, cancellation, resource and failure contracts; public owning fields and source maps cannot safely become borrowed views without ABI/lifetime changes. A narrow shared contract kit or private adapter can be evaluated later with ownership, cancellation and parity evidence. Existing families are delivered through their own bounded pipelines, not an invented unified implementation.
- Native flip-model automatic occlusion detection, eviction-stable cold cache keys, broad text-store copy removal and other unmeasured architecture/performance prescriptions remain proposals where the current supported contract is coherent. No performance gain or rejection is based merely on untested source similarity.
- CR21's opening-key WM_CHAR remains historically unreproduced; filtering it without a trigger could eat a real keystroke. CR34's accepted archive/raw relocation and single history rewrite are not performed; original asset/privacy scope, verified backup, retention and consumer pin protections remain administrative work. No existing ref or history is represented as changed.
- PopupReadiness's earlier healthy-state probe lacks the captured elapsed/lifecycle facts needed for retrospective attribution. Preserve the failure and current bounded diagnostics; a later green run does not establish its cause. The accepted disposition challenges the impossible historical causation demand without asserting a cause.
- Unified CI now specifies compiler-free PR checks and separately quiet native main qualification (`Specs/Build/Build_UnifiedCI.md`). This supersedes the old paired-PR workflow recommendation in scope; it is not a claim that the old trusted-base paired PR gate ran or that benchmark policy is qualified.
