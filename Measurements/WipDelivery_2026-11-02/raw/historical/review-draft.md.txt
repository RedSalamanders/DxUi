## Impact and compatibility

The delivery changes lifetime and reentry handling, input, Grid/Tree, menu/UIA, embedded focus and resources, build/test evidence, and bounded RichMarkdown, math, diagrams, images, file drop and export. Native visibility is application-supplied; it does not infer arbitrary covered-window occlusion. UIA radio groups now expose real selection-container semantics and embedded action hints remain bounded. Durable product contracts remain in the repository's UI, rendering, build and rich-text specifications.

The API revision remains 4, but public C++ object layouts changed. A consumer must rebuild its entire dependent binary closure with the exact matching headers, library, toolset, configuration and runtime. A matching API number alone is not binary compatibility; compatibility branch build and consumer adoption are separately qualified.

The retained same-toolset R25 Release [size comparison](release-size-r25.json) is across the full feature batch, not an isolated compiler experiment. The sample `DxUi.EmbeddedControls.exe` grew from 2,019,840 to 3,586,048 bytes (+77.54%); the LTCG library archive grew from 189,760,522 to 236,089,884 bytes (+24.41%). Sample growth is material and requires an owner decision; archive size is not installed-image size. No performance acceptance follows from these observations.

## Challenged prescriptions and boundaries

- W2.8/editor-05: bounded pending/raw windows were implemented, but some prepared v0, visual and source-fallback actions still materialize whole text. The universal zero-copy prescription is rejected for this delivery: the existing segmented ownership, grapheme/CRLF context and source-affinity/history semantics make a reader redesign nontrivial, with no demonstrated regression justifying its storage and parity cost. This is residual bounded linear work, not a completed optimization or an external hold.
- W2.9 early tree release conflicts with retaining the last good immutable parser publication through pending and canceled work. The separate sorted-vector proposal remains unimplemented and unmeasured; duplicate ordering, one-use and cooperative budgets must be preserved.
- W2.10 a single EOL-selection policy would conflate raw typing/paste with local structural edits. Scanner factoring remains optional and is not claimed implemented. W4/W5 mandatory generic lifecycle/public-field replacements are challenged because publication, cancellation, ownership, error and ABI rules differ across the parser, builder, geometry and image services. Optional proposals remain proposals, not delivered changes.
- Native math, diagrams, HTML and SVG use explicitly bounded supported profiles and preserve unsupported source. They are not full TeX, Mermaid or browser implementations. Application UI, decoding and network policy remain application-owned where their contracts say so.
- Real WIC and DC targets on this host returned Context7 successfully. A forced `E_NOINTERFACE` path covers the fallback contract; an actual SDK QI miss was not observed. The owner accepted real-success plus forced-failure evidence for this host without claiming an actual miss.
- CR21 opening-key `WM_CHAR` remains historically unreproduced; a speculative filter could discard a genuine first keystroke. CR34 archive relocation and one history rewrite are administrative work with retained privacy, backup, ownership and consumer-pin constraints; they were not performed. PopupReadiness's old healthy-state observation lacks the timing/lifecycle facts needed to establish its cause; current diagnostics or a later pass cannot retrospectively prove that cause.
