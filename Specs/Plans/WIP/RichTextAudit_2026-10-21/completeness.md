# RichText completeness: Markdown, mathematics and Mermaid

Appendix to [the audit plan](../RichTextAudit_2026-10-21.md). Three inventory agents compared the shipped
engine at `fa5821c8` with the pinned references under `ThirdParty/Markdown` (CommonMark/GFM corpora, KaTeX
0.16.11 support tables, Mermaid 11.4.1 documentation) and with what users expect from a complete Markdown editor.
These inventories used a cheaper model, as the owner requested; the lead reviewed them and the plan, not this
appendix, owns sequencing. Entries are proposals until the owner accepts their scope. Each keeps the existing
rules: owned C++ only, bounded admission before allocation, exact editable source for anything unsupported,
no browser, script or network helper, and no work during composition.

Status values: *missing* (absent), *partial* (exists with material gaps), *wrong-behavior* (exists and
misbehaves), *stale-doc* (status text disagrees with code). Priority reflects how common the construct is in
ordinary technical Markdown. Effort is a rough small/medium/large estimate. IDs are stable references for the plan.

## Markdown rendering and editing

The owned parser already passes all 1,324 pinned CommonMark 0.31.2 and GFM 0.29 vectors, so the Markdown gap is in
presentation, interaction and editing, not in parsing. The highest-value library work is a small set of shared
enablers (decoration ranges, selection-changed and link-activated events, scroll API) that many later features reuse,
then editing fidelity (undo coalescing, Enter and soft-break policy, context menu, find/replace, missing commands),
then rendering fidelity (theme palette roles, code-block presentation, content-aware tables, the HTML subset).
Application-owned pieces (dialogs, URL policy, spell-check dictionaries, persistence) stay in consumer adapters.

### Supported today

- Parsing: owned lossless parser passes 652 CommonMark 0.31.2 + 672 GFM 0.29 vectors; ATX and setext headings both map to SemanticRole::Heading (DxUi.RichSemanticDocument.cpp:166-175) and render at six scale steps (1.15x-1.9x, DxUi.RichTextLayout.cpp:268-273); SetHeading edits setext underlines locally.
- Inline rendering: strong, emphasis, GFM ~~strike~~, inline code (monospace family), links (underlined, inherited ink), URI/email/extended autolinks, soft break (as space) and hard break (as newline), decoded escapes/entities, color emoji (D2D1\_DRAW\_TEXT\_OPTIONS\_ENABLE\_COLOR\_FONT, DxUi.RichTextLayout.cpp:484).
- Blocks: nested block quotes (one 2-DIP bar per level, 16-DIP indent, DxUi.RichSemanticGeometry.cpp:1685-1689), ordered/unordered/nested lists with a measured shared hanging gutter and RTL mirroring, task lists (click, Ctrl+Enter and UIA Toggle), GFM tables with declared column alignment and RTL column reversal, thematic-break hairline, fenced and indented code (monospace + outline), footnotes with reordered footer bodies and repeated backlinks.
- Rich objects: bounded balanced native HTML subset with whole-leaf literal fallback; local raster images (PNG/JPEG/BMP/GIF/TIFF, first frame, EXIF orientation) through a caller-owned worker; inline and display TeX-subset math via native DirectWrite glyph layout (Cambria Math); Mermaid flowchart, stateDiagram and classDiagram subsets drawn natively with host-theme text/stroke/fill brushes; unsupported syntax stays exact editable source with ranged diagnostics.
- Editing commands (RichTextCommands.h:6-27): InsertParagraph, SetList/Indent/Outdent, JoinBackward/Forward, SetHeading 0-6, ToggleStyle (strong, emphasis, strike, code), SetLink/RemoveLink, ToggleTask, InsertTable, table row/column insert/delete, SetTableCell, Next/PreviousTableCell; all source-exact, atomic and undoable; visual deletion removes empty owned wrappers.
- Keyboard/mouse: caret/word/line/document navigation, Shift extension, PageUp/PageDown, Ctrl+A/C/X/V/Z/Y, Ctrl+Shift+Z, Ctrl+B/I, Ctrl+Enter (task/footnote), Enter list/table continuation, Tab/Shift+Tab table-cell and list indent, F2/Esc source-region editing, Ctrl+click footnote navigation, pointer selection with capture, double-click word, wheel scroll (48 DIP/detent), AltGr and surrogate input, file-reference paste (images/links) as one undo transaction.
- Platform: source TSF/IME + UIA Text/Text2/TextEdit/Document providers, semantic UIA children, table patterns and task Toggle, native and embedded hosting, RTL flow direction, reduced-motion caret, Source/Rich view toggle, read-only mode, exact-source clipboard copy.

## Mathematics

The native engine is a bounded, all-or-nothing TeX subset: about 137 command names and 10 environments against about
932 KaTeX 0.16.11 commands, roughly 15 percent. It renders plain glyph runs in Cambria Math with stroked rules and
has no TeX style machine, atom classes, display/inline distinction or OpenType MATH use. Fidelity matters more than
breadth for ordinary documents: math italic, atom spacing, limits placement, display style and correct spacing
widths affect almost every formula. Breadth is cheapest through one generated, class-annotated symbol table pinned
to KaTeX data. User macros, packages and trust-gated commands stay out of scope.

### Supported today

- STRUCTURE (DxUi.NativeMath.cpp Parser::Atom/Row): braced groups {..}; superscript ^ and subscript \_ (either order, one each; duplicates rejected, matching KaTeX); \\frac, \\dfrac, \\tfrac (all three produce the same Fraction node, no display/text style difference); \\sqrt{..} and \\sqrt[n]{..} (index parsed by a nested ParseMath up to the FIRST ']' so brackets inside the index are unsupported); single-token arguments (\\frac12, \\sqrt x, \\mathbf x).
- FONT/STYLE (lines 213-221): \\text{..}, \\operatorname{..} (both a plain Text leaf, argument must be a braced group whose only legal escapes are \\{ \\} \\% \\\_ \\\$ \\& \\# \\\\ and backslash-space); \\mathrm (no-op), \\mathbf (bold weight), \\mathit (italic), \\mathbb and \\mathcal (parse-time remap to Unicode double-struck/script code points; blackboard also maps digits and lowercase). Nothing else sets a font; there is no automatic math italic.
- ACCENTS (line 222): \\overline, \\underline, \\bar, \\hat, \\widehat, \\vec, \\dot, \\ddot. Drawn as stroked line segments in PreparedMath::Place, not font glyphs; \\bar==\\overline, \\hat==\\widehat.
- DELIMITERS (lines 141-175, 225-239): \\left..\\right with ( ) [ ] { } \| . \\{ \\} \\\| \\langle \\rangle \\lbrace \\rbrace \\vert \\Vert (note \\\| yields a single bar, see gaps); body height scales; fences are stroked polylines. \\big \\Big \\bigg \\Bigg + the same delimiter set produce an ordinary-size Text glyph (no size change); '.' gives zero-width Space.
- LIMITS CONTROLS (240-241): \\limits and \\nolimits are accepted anywhere and produce an empty Space node (no behaviour change).
- SPACING (242-243, 353-357): \\quad (2 x 0.25em = 0.5em), \\qquad (1.0em), \\, \\; \\: and backslash-space (all one 0.25em), \\! (zero width). Plain whitespace in math mode is skipped (iswspace).
- ESCAPES (358): \\{ \\} \\% \\\_ \\\$ \\& \\# and \\\\ (the last renders a literal backslash glyph outside a matrix cell).
- SYMBOL TABLE (lines 244-349, 106 name->Unicode entries, linear scan): lowercase Greek alpha beta gamma delta epsilon varepsilon zeta eta theta vartheta iota kappa lambda mu nu xi pi rho sigma tau upsilon phi varphi chi psi omega; uppercase Gamma Delta Theta Lambda Xi Pi Sigma Phi Psi Omega; big operators sum prod int iint iiint oint (plain base-size glyphs); infty partial nabla; times cdot div pm mp; le leq ge geq ne neq approx equiv sim propto; rightarrow leftarrow leftrightarrow Rightarrow Leftarrow Leftrightarrow to mapsto; ldots cdots vdots ddots; in notin subset subseteq supset supseteq cup cap emptyset forall exists neg land lor; langle rangle lbrace rbrace vert Vert; named functions sin cos tan cot sinh cosh log ln exp lim max min det gcd (plain upright Text, no thin space, no limits placement).
- ENVIRONMENTS (Matrix(), lines 102-140): matrix pmatrix bmatrix Bmatrix vmatrix Vmatrix smallmatrix cases aligned gathered. Rows split by \\\\, cells by &; all rows must have equal column counts; cases \<=2 columns; gathered exactly 1 column; aligned right/left alternating columns; fences are stroked.
- RAW INPUT: any other Unicode scalar (including supplementary-plane surrogate pairs, Greek/operator/arrow literals) is accepted as a Text atom; every char except } ^ \_ & # \$ is accepted raw, including ' % ~ " and \< > = + -. Adjacent Text atoms are merged into one DirectWrite run (Row, lines 413-414).
- LIMITS IN CODE: 4096 source UTF-16 units (MathMaximumSourceUnits, RichMath.h:9), 512 nodes (NativeMath.cpp:34 and :449), nesting 24 (Atom :178, GroupText :87, tree count :442), 16 rows (:135), 16 columns (:112), 128 cells total (:112), per document 4096 math records and 128 combined native objects (RichSemanticDocument.cpp:329-330). All-or-nothing: any rejection preserves the whole formula as literal source with an UnsupportedMath diagnostic (RichSemanticDocument.cpp:343-345).
- RENDER (PreparedMath.h): font Cambria Math, size = editor font x 1.15 (RichSemanticGeometry.cpp:147), scripts 0.64, fraction operands 0.86, one DWrite layout per Text leaf created one per Advance(), final Advance() does Measure+Place for the whole tree, Draw replays cached layouts and strokes with the caller brush. Formulas wider than the view are uniformly scaled down (RichSemanticGeometry.cpp:773, :815).
- COVERAGE SUMMARY: 137 distinct command names (106 symbol entries + 31 structural/function names) against 932 KaTeX 0.16.11 command rows not marked 'Not supported' in support\_table.md.txt (about 14.7 percent). Approximate per-section coverage of supported.md.txt names: Accents 9/39, Delimiters 12/61, Big operators 6/20, Binary operators 9/65, Fractions/binomials 3/13, Math operators 16/54, Relations 13/141, Negated relations 3/59, Arrows 8/110, Symbols/punctuation 7/105, Style/color/size/font 11/65, Spacing+overlap 7/32, Annotation 3/16, Environments 6/10 (+1/7 'other' environments), Letters/Unicode 39/112, Logic/set 13/29.

## Mermaid diagrams

The native engine is a small, bounded, fail-closed subset: 13 of the 105 pinned flowchart examples are admitted,
roughly 8 of 20 stateDiagram fences and 3 of 31 classDiagram fences parse correctly, and none of the other 18
families. Counts other than the 13/105 flowchart figure are hand-traced estimates, not executed measurements.
Real-world value comes first from flowchart parity (subgraphs, edge styles and inline edge text, more shapes,
line breaks in labels, styling) and from robustness (direct edge routing instead of exterior lanes, label wrapping,
per-object fallback), then from a family-neutral diagram interface, then sequenceDiagram as the next family.

### Supported today

- INTEGRATION: RichMarkdown profile only; a fenced code block whose info string is exactly 'mermaid' (case-sensitive, trailing blanks allowed; any other option yields an UnsupportedDiagram diagnostic; CommonMark/GFM keep ordinary code). The body is parsed after container-prefix removal and EOL normalization with provenance back to original source (src/Controls/DxUi.RichSemanticDocument.cpp:539-566, SemanticExtensions.h:19-33).
- LIMITS: 16,384 body units, 256 nodes, 512 edges, 1,024 non-empty statements (header counts), 1,024 decoded label units, 128 identifier units (NativeFlowchart.h:105-106); 128 mermaid candidates per document and 32,768 node+edge records per document (SemanticExtensions.h:37); 128 combined native placements shared with math and images (RichImageResources.h:26); 65,536 DIP geometry extent per axis (NativeFlowchartLayout.h:65).
- OUTCOMES: Prepared / Unsupported / Malformed / Capacity from the parser, plus Empty, Unclosed and fence-option diagnostics from the semantic builder. A rejected diagram exposes no partial graph, keeps the exact fenced source with a ranged diagnostic (whole scalars and CRLF pairs) and UIA help text. A Prepared graph becomes one atomic object character with Image-role alternative text (direction, 'id = label' list, connections); F2 or UIA Invoke opens the exact source in place; Esc/F2/Ctrl+Enter returns.
- SCHEDULING: parser advances one UTF-16 unit per work unit (one statement parse is indivisible); layout handles one node, edge, DFS transition or rank per event; DWrite shaping spends one SDK-layout allowance per label (empty node labels included); paint uses only cached labels and path geometries; identical requests coalesce and cancel/replace leaves the previous publication valid.
- FLOWCHART header: 'flowchart' or 'graph' followed by one required direction TB, TD, BT, LR or RL. Statements end at CR, LF, CRLF or a semicolon outside quotes/brackets/pipes. '%%' comments (full-line and trailing, outside labels) are ignored; '%%{...}' is rejected as UnsupportedConfiguration.
- FLOWCHART identifiers: ASCII [A-Za-z\_][A-Za-z0-9\_]\* up to 128 units, case-sensitive identity, first-seen node order. Reserved words end, subgraph, direction, style, class, classDef, click, linkStyle are rejected as UnsupportedStatement.
- FLOWCHART node shapes (4 of the 13 legacy Mermaid shapes): bare id, [text] rectangle, (text) rounded, ((text)) circle, {text} rhombus/diamond. Re-declaration with an explicit label replaces label+shape (last text wins); a bare endpoint reference preserves the earlier declaration (matches flowchart.md.txt 'A node with text').
- FLOWCHART labels: unquoted (surrounding blanks trimmed; may not contain []\(){};" or the markup characters \< > & # ' , '\$\$' or icon prefixes) or quoted with any Unicode scalar text; escapes backslash-quote, double backslash and backslash-n (newline); at most 1,024 units.
- FLOWCHART edges: '-->' (arrowhead) and '---' (open line), optionally followed by \|label\| (quoted or unquoted), chains 'A --> B --> C', cycles, self-loops and parallel edges, single-space-around-link forms, trailing semicolons. 'A---oB' and 'A---xB' are rejected explicitly instead of becoming ids oB/xB (matches the flowchart.md.txt warning); 'A-->oB' correctly parses as an arrow to node oB.
- FLOWCHART layout (NativeFlowchartLayout): first-seen DFS removes back edges and self-loops, longest-path ranks over the DAG, one row per rank in declaration order, four orientations without rotating text, shape containment of padded measured labels (diamond 2x, circle on label diagonal), every edge gets its own exterior orthogonal six-point lane, labels placed in the lane, whole-diagram extent admission, stable cooperative events.
- FLOWCHART rendering (PreparedFlowchart): DWrite labels in the host font/size/locale/reading direction with logical and ink metrics (Unicode, bidi, multiline), rectangle/rounded(8 DIP)/ellipse/diamond fills and strokes, solid 1-DIP polylines, one filled 8x8 DIP arrow triangle, edge labels painted last over a 2-DIP padded opaque backing, transform restore, factory-identity and typography/resource-epoch coalescing.
- STATE DIAGRAM: headers 'stateDiagram' and 'stateDiagram-v2' (both reuse the flowchart engine); 'direction TB\|TD\|BT\|LR\|RL'; a bare id declares a state (rounded); state 'long name' as id (quoted alias, requires 'as '); 'id : description' (appended as an extra label line); transitions 'A --> B' with optional ': label' and chains; '[\*]' as source = shared start node and '[\*]' as target = shared end node (circle with bullet glyphs); '%%' comments. First pinned example (after the YAML title header is removed) = 5 nodes, 6 transitions.
- CLASS DIAGRAM: header 'classDiagram' (not '-v2'); 'direction'; 'class Name' declaration (rectangle); 'Name : member' lines appended to the node label; relationships '\<\|--' and '--\|>' (arrowhead at the parent, synthetic edge label 'inherits' unless overridden), '-->' association, '--' plain link, each with optional ': label'; 'class Name[quoted label]' works only through the shared flowchart label syntax; '%%' comments.
- REFERENCE ACCOUNTING: 24 pinned files with hashes (22 syntax docs + flow.jison + LICENSE; hashes verified equal to the generator pins); all 105 mermaid fences of flowchart.md classified independently: 13 Prepared, 92 Unsupported (58 expanded-shape, 15 expanded-edge, 6 click/style/class, 5 subgraphs, 4 entities/html/icons, 2 metadata, 2 config/markdown); first fence of each of the other 20 family docs checked (state Prepared, other 19 Unsupported).
- COVERAGE (measured/hand-traced here): flowchart 13/105 official examples (12%); state about 8 of 20 pinned fences (hand-traced from stateDiagram.md.txt: simple, older renderer, id, alias, description, transition, label, start/end, comments); class about 3 correctly accepted of 31 fences plus 2 silently mis-rendered (lollipop, css-class shorthand); all other 18 families and examples.md 0 of 9.
